01 - ما هو Backend؟

عندما تفتح موقعًا وتضغط على زر تسجيل الدخول، فأنت ترى الواجهة الأمامية، لكن خلف هذه الواجهة توجد أنظمة تستقبل البيانات وتتحقق منها وتحفظها وتعيد النتيجة. هذا الجزء يسمى Backend.

الفكرة الأساسية

Frontend = ما يتعامل معه المستخدم مباشرة.

Backend = المنطق والبيانات والخدمات التي تعمل خلف الواجهة.

مثال بسيط

المستخدم يكتب: البريد الإلكتروني + كلمة المرور. الواجهة ترسل البيانات إلى Backend. Backend يتحقق من البيانات. ثم يطلب من قاعدة البيانات المعلومات المطلوبة. وفي النهاية يعيد نتيجة إلى الواجهة.

ماذا يمكن أن يبني Backend؟

  • نظام تسجيل وإنشاء حسابات.
  • نظام أصدقاء ورسائل.
  • حفظ بيانات الألعاب.
  • متجر إلكتروني.
  • نظام غرف ومستخدمين.
  • API لتطبيقات الهاتف.
  • لوحة تحكم.
  • نظام ملفات ورفع صور.

02 - Server: أين يعمل Backend؟

Server هو جهاز أو نظام يعمل باستمرار تقريبًا ويستقبل الطلبات من المستخدمين. يمكن أن يكون جهازًا حقيقيًا أو خادمًا افتراضيًا داخل مركز بيانات.

المسار الأساسي

[ المستخدم ]
     |
     v
[ المتصفح / التطبيق ]
     |
     v
[ Backend Server ]
     |
     v
[ Database ]

الرسم باستخدام الأشكال

  • ● Circle = المستخدم أو العميل Client
  • ■ Square = الخادم Server
  • ◆ Disc = قاعدة البيانات Database

الفكرة: العميل يرسل طلبًا إلى المربع، والمربع يتعامل مع القرص ثم يعيد النتيجة إلى العميل.

ما الذي يفعله الخادم؟

  • يستقبل الطلبات.
  • يشغل كود Backend.
  • يتعامل مع قواعد البيانات.
  • يتحقق من الصلاحيات.
  • يرسل الاستجابات.

03 - HTTP: لغة التواصل بين العميل والخادم

عندما يتحدث المتصفح مع الخادم، يحتاجان إلى طريقة منظمة للتواصل. HTTP هو أحد أهم الأساسات التي ستقابلها في Backend.

Request

الطلب الذي يرسله العميل إلى الخادم.

Response

الاستجابة التي يعيدها الخادم إلى العميل.

أهم طرق HTTP

  • GET - الحصول على بيانات.
  • POST - إرسال أو إنشاء بيانات.
  • PUT - تحديث بيانات.
  • PATCH - تعديل جزء من البيانات.
  • DELETE - حذف بيانات.

مثال

GET /users

المعنى: أريد الحصول على المستخدمين. 

POST /users

المعنى: أريد إنشاء مستخدم جديد.

04 - API

API هو واجهة منظمة تسمح لبرنامج بالتحدث مع برنامج آخر. في Backend ستستخدم API كثيرًا لكي تجعل التطبيقات والواجهات تتواصل مع الخادم.

مثال API

GET /api/users/15

يمكن أن يعيد الخادم بيانات المستخدم رقم 15 بصيغة JSON. 

{
  "id": 15,
  "name": "Ali",
  "level": 7
}

لماذا API مهم؟

  • تطبيق الهاتف يمكنه استعماله.
  • موقع الويب يمكنه استعماله.
  • لعبة يمكنها استعماله.
  • برنامج آخر يمكنه استعماله.

05 - قواعد البيانات

Backend يحتاج غالبًا إلى مكان يحفظ فيه المعلومات. هنا تأتي Database.

مثال

لو كان لدينا موقع حسابات، فقد نحتاج إلى حفظ:

  • رقم المستخدم.
  • الاسم.
  • البريد الإلكتروني.
  • كلمة المرور بشكل آمن.
  • تاريخ إنشاء الحساب.

نوعان مهمان

SQL

البيانات تكون منظمة غالبًا في جداول وعلاقات. من أمثلتها MySQL وPostgreSQL وSQLite.

NoSQL

توجد طرق مختلفة لتنظيم البيانات، وتستخدم بعض الأنظمة مستندات أو أشكالًا أخرى. من الأمثلة MongoDB.

مثال جدول Users

id name email
1 Ali ali@example.com
2 Sara sara@example.com

CRUD

  • Create = إنشاء.
  • Read = قراءة.
  • Update = تحديث.
  • Delete = حذف.

CRUD من المفاهيم التي يجب أن تفهمها جيدًا لأنها تظهر في عدد كبير من تطبيقات Backend.

06 - الحسابات وتسجيل الدخول

عندما ينشئ شخص حسابًا، لا يكفي أن نضع اسمه وكلمة مروره في قاعدة البيانات بطريقة عادية. يجب تصميم نظام حسابات آمن.

التسجيل

  1. المستخدم يرسل بيانات التسجيل.
  2. Backend يتحقق من البيانات.
  3. يتأكد من عدم تكرار الحساب بطريقة غير صحيحة.
  4. يخزن كلمة المرور باستخدام hashing مناسب.
  5. ينشئ الحساب.

تسجيل الدخول

  1. المستخدم يرسل بيانات الدخول.
  2. Backend يبحث عن الحساب.
  3. يتحقق من كلمة المرور.
  4. ينشئ جلسة أو رمز وصول مناسب.
  5. يسمح للمستخدم بالوصول إلى الموارد المصرح بها.

مصطلحات مهمة

  • Authentication = من أنت؟
  • Authorization = ماذا يسمح لك أن تفعل؟
  • Session = جلسة المستخدم.
  • Token = رمز يستخدم في بعض أنظمة المصادقة.
  • Password Hash = تمثيل آمن لكلمة المرور بدل تخزينها كنص عادي.

07 - أمان Backend

Backend يتعامل مع بيانات المستخدمين، لذلك الأمان ليس إضافة تجميلية. يجب التفكير فيه منذ تصميم النظام.

أشياء أساسية يجب تعلمها

  • عدم تخزين كلمات المرور كنص عادي.
  • التحقق من البيانات القادمة من المستخدم.
  • استخدام HTTPS عند الحاجة.
  • حماية مفاتيح API والأسرار.
  • منع الوصول غير المصرح به.
  • التعامل الصحيح مع أخطاء الخادم.
  • فهم SQL Injection وطرق الوقاية منه.
  • فهم CSRF وXSS وطرق تقليل المخاطر المناسبة للنظام.
  • تحديث المكتبات والاعتماديات.
  • عدم وضع الأسرار داخل الكود المنشور.

08 - لغات وتقنيات Backend

لا توجد لغة واحدة اسمها Backend. Backend هو مجال، ويمكن بناء أنظمته بلغات وتقنيات متعددة.

لغات شائعة

  • Python
  • JavaScript / TypeScript
  • Java
  • C#
  • Go
  • PHP
  • Ruby
  • Kotlin
  • Rust

ماذا نتعلم أولًا؟

لا تحاول تعلم كل هذه اللغات في الوقت نفسه. اختر لغة واحدة، ثم تعلم بها أساسيات Backend. بعد فهم المفاهيم، تصبح الانتقال إلى لغة أخرى أسهل بكثير.

مثال مسار بسيط

Python → HTTP → API → Database → Authentication → Security → Deployment

09 - تنظيم مشروع Backend

المشروع الجيد لا يكون ملفًا ضخمًا يحتوي كل شيء. مع زيادة حجم المشروع نحتاج إلى تقسيم المسؤوليات.

مثال تنظيمي

project/
|
+-- server/
|   +-- routes/
|   +-- controllers/
|   +-- services/
|   +-- models/
|   +-- middleware/
|   +-- config/
|
+-- tests/
|
+-- README

الفكرة

  • Routes = تحديد المسارات.
  • Controllers = استقبال الطلب وتنظيم العملية.
  • Services = منطق العمل.
  • Models = التعامل مع البيانات.
  • Middleware = وظائف تمر عليها الطلبات.
  • Config = إعدادات المشروع.
  • Tests = اختبار النظام.

10 - النشر والاستضافة

بناء Backend على جهازك هو مرحلة التطوير. لكي يستطيع الآخرون استخدامه، يجب تشغيله على بيئة يمكن الوصول إليها.

مصطلحات ستقابلها

  • Hosting = استضافة المشروع.
  • Domain = اسم الموقع.
  • DNS = نظام يربط أسماء النطاقات بعناوين الشبكة.
  • Port = منفذ خدمة الشبكة.
  • Environment Variables = إعدادات أو أسرار خارج الكود.
  • Logs = سجلات تساعد على معرفة ما يحدث داخل الخادم.
  • Process = البرنامج الذي يعمل على الخادم.

قبل النشر

  • اختبر API.
  • راجع الأمان.
  • لا تضع الأسرار في Git.
  • تأكد من إعداد قاعدة البيانات.
  • جهز طريقة مراقبة الأخطاء والسجلات.

11 - المشروع التطبيقي: نظام غرف وأصدقاء

الآن نجمع الأفكار السابقة في مشروع قريب من التطبيقات الحقيقية: موقع يسمح للمستخدم بإنشاء حساب، إضافة أصدقاء، وإنشاء غرفة باستخدام كود.

الجزء الأول: الحساب

  • إنشاء حساب.
  • تسجيل الدخول.
  • تسجيل الخروج.
  • صفحة المستخدم.

الجزء الثاني: الأصدقاء

  • إرسال طلب صداقة.
  • قبول الطلب.
  • رفض الطلب.
  • عرض قائمة الأصدقاء.

الجزء الثالث: الغرف

  • إنشاء غرفة.
  • توليد كود للغرفة.
  • إدخال الكود للانضمام.
  • التحقق من صلاحية الغرفة.
  • حفظ المشاركين.

12 - طريق التعلم المقترح

لا تبدأ بكل شيء دفعة واحدة. تعلم Backend على شكل طبقات.

  1. المرحلة 1: الأساس
    ما هو Backend؟ ما هو Server؟ ما هو Client؟ وكيف تتواصل البرامج؟
  2. المرحلة 2: HTTP
    Request، Response، Methods، Status Codes، Headers.
  3. المرحلة 3: لغة واحدة
    اختر لغة Backend واحدة وتعلم أساسياتها جيدًا.
  4. المرحلة 4: API
    اصنع API بسيطًا يعيد بيانات.
  5. المرحلة 5: Database
    تعلم الجداول أو طريقة تخزين البيانات، ثم CRUD.
  6. المرحلة 6: Authentication
    حسابات، تسجيل دخول، جلسات أو Tokens، وصلاحيات.
  7. المرحلة 7: Security
    تعلم كيف تحمي البيانات والطلبات والأسرار.
  8. المرحلة 8: مشروع
    ابنِ نظامًا حقيقيًا بدل الانتقال مباشرة إلى موضوع جديد.
  9. المرحلة 9: Deployment
    انقل المشروع من جهازك إلى بيئة يمكن للمستخدمين الوصول إليها.
  10. المرحلة 10: المستوى المتقدم
    Caching، Queues، WebSockets، Scaling، Load Balancing، Docker، Monitoring وArchitecture.

قاموس Backend السريع

Backend
الجزء الذي يعمل خلف الواجهة ويتولى المنطق والبيانات والخدمات.
Frontend
الجزء الذي يتعامل معه المستخدم مباشرة.
Client
برنامج يرسل طلبات إلى خدمة، مثل المتصفح أو تطبيق الهاتف.
Server
النظام الذي يستقبل الطلبات ويعالجها ويرسل الاستجابات.
API
واجهة منظمة للتواصل بين البرامج.
Database
نظام لتخزين البيانات وإدارتها.
HTTP
بروتوكول أساسي للتواصل عبر الويب.
JSON
صيغة شائعة لتمثيل البيانات وإرسالها بين الأنظمة.
Authentication
التحقق من هوية المستخدم.
Authorization
تحديد ما الذي يسمح للمستخدم بفعله.
CRUD
Create, Read, Update, Delete.

بعد هذه المنطقة

بعد فهم هذه الصفحة، لا تنتقل مباشرة إلى عشرات التقنيات. الخطوة الأفضل هي اختيار لغة واحدة وبناء Backend صغير بها.

الترتيب المقترح: لغة برمجة → Server بسيط → HTTP → API → Database → Authentication → Security → مشروع → Deployment.

الهدف ليس حفظ أسماء كثيرة، بل فهم كيف تنتقل البيانات من المستخدم إلى الخادم ثم إلى قاعدة البيانات وتعود النتيجة إلى المستخدم.
